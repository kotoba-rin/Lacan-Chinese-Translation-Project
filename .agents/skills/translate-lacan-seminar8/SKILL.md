# Translate Lacan Seminar VIII

把指定课次直接写入项目的权威译文文件，同时保证语义、信息量、段落 ID、注释、术语和构建结果都可核验。

## 固定路径

- 原文：`texts/s8-le-transfert/original/Leçon-xx.md`
- 译文：`texts/s8-le-transfert/translation/Leçon-xx.md`
- 术语表：`texts/s8-le-transfert/glossary.md`
- 格式样例：`references/format-examples.md`
- 课次校验：`scripts/validate_lesson.py`

始终从用户指定的课次或路径解析 `Leçon-xx.md`。若目标译文已经存在，直接在原文件中续写或校订，不要重建并覆盖用户已有内容。

## 组合使用 humanizer-zh

在开始工作时同时使用 `$humanizer-zh`，完整读取其 `SKILL.md`，把它安排在语义初译之后、最终校验之前。skill 之间是由 Codex 组合执行的工作流，不是代码函数调用；不要在 `agents/openai.yaml` 中虚构 `dependencies.skills`，该依赖区只用于受支持的工具依赖。

若 `$humanizer-zh` 不可用，不得跳过润色：执行本 skill 的“中文润色门槛”，并在交付时说明伴随 skill 缺失。

`$humanizer-zh` 只负责改善中文表达，不是翻译正确性的裁判。每次润色后都必须回到法语原文逐段复校；不得因为润色后的中文更顺畅，就默认其语义正确。

## 不可省略的规则

1. **段落 ID 一一对应**
   - 读取原文中的全部 `<!-- id: ... -->`，在译文中保持相同数量、相同顺序和相同值。
   - 每个 ID 下必须有非空译文；不得残留 `<!-- untranslated -->`。
   - 新翻译不得合并、拆分或重编号 ID，不得新加 `<!-- ids: ... -->`。
   - 若旧译文已含 `<!-- ids: ... -->`，先核对原文和构建规则；除非用户明确要求重构，不要擅自删除既有映射。

2. **原文脚注转成课内编号注释**
   - 识别正文脚注引用（如 `[^173]`）及文末定义，按本课出现顺序重编号为 `[注1]`、`[注2]`……。
   - 在对应译文正文中保留 `[注N]` 引标，并紧接该译文段落写：
     `> [注N] 注释译文`
   - 完整翻译原注，不得只译标题或省略续行、出处、页码、双关说明和原注中的图片。
   - 不把源文件末尾的 `[^...]` 定义原样复制进译文。

3. **新增译注必须有正文引标**
   - 典故、出处、双关、文化背景或必要的理解说明，在相关译文位置插入 `[注]`，并在段落后写：
     `> [注] 译注内容`
   - 若同一段已有原文编号注释，先列所有 `> [注N]`，再列新增的 `> [注]`。
   - 不得只写段后 `> [注]` 而遗漏正文中的 `[注]`。

4. **义译保留直译**
   - 只有确实改变字面形态的成语、习语、双关或文化表达才标注，不给普通语序调整滥加说明。
   - 使用：`自然义译（直译：……）`。
   - 若还需要解释，再加正文 `[注]` 和段后译注。

5. **多义、歧义和不确定处不得强行定译**
   - 使用：`译法A/译法B（原文：……）[注]`。
   - 段后写 `> [注]`，说明句法、词义范围、上下文依据和当前倾向。
   - 若歧义来自转录残缺、标点异常或版本问题，明确说明证据不足，不把推测写成定论。

6. **术语表是权威来源**
   - 翻译前读取当前 `glossary.md`，正文严格对齐现有统一译名和备注中的语境限制。
   - 不从记忆沿用可能已经过时的译名；实时文件优先。
   - 识别出新的概念、人名、篇名、学派、希腊词或固定表达时，在同一轮更新术语表的相应分区。
   - 添加前搜索外文、变体和中文译名，避免重复行；说明本课语境，而不是只填一对裸词。
   - 概念性的 `sujet` 译“主体”，正文不逐处加 `(sujet)`；普通“议题”义按当前术语表处理。

7. **保留项目 Markdown 结构**
   - 保留 frontmatter、标题、`source-original`、`seminar`、`lesson`、图片、公式、段落 ID 等结构性 HTML 注释，以及有意的 Markdown 换行。
   - 不得保留 `<strong>`、`<em>`、`<img>`、`<span>` 等可见 HTML 格式标签；用 `**粗体**`、`*斜体*`、Markdown/Obsidian 图片语法等对应格式替换。结构性 `<!-- id: ... -->` 与 `<!-- ids: ... -->` 不属于可见格式标签，不得误删。
   - 图片优先引用原文资源，例如：`![[texts/s8-le-transfert/original/assets/image8.jpeg|320]]`。
   - 只编辑权威源文件，不直接修改 `build/` 或 `book/` 作为最终成果。

8. **信息保真优先于中文流畅度**
   - 翻译与润色首先要保全原文的信息量、论证关系和语义限制；自然中文不能以删减、概括、解释性替换或逻辑简化为代价。
   - 不要一味认可已有初译或润色结果。法语原文、活术语表与上下文证据优先；发现润色引入偏差时，直接回改译文。
   - 中文自然度与信息完整度冲突时，优先保留信息，即使句子因此略显密集。可以重组句法，但不得擅自降低原文的重复、限定、犹疑、自我修正或概念区分。
   - 无法在正文中同时保全自然度与信息度时，在相关位置添加 `[注]`，并在段后写 `> [注]`，明确说明义译造成的侧重变化、无法保留的双关、语义损失或信息差异。不得用译注掩盖本可修正的错译。

9. **humanizer-zh 后必须逐段回校法文**
   - 润色不是终稿。润色完成后，按原文 ID 顺序，把法语原文与润色后的中文逐段、逐意义单元重新核对，不得只抽查难句。
   - 至少检查：主客体与指代、肯定与否定、情态强度、时态和时间关系、因果与转折、条件与范围、论证方向、术语差异、列举项、重复与自我修正、隐喻与双关。
   - 重点寻找润色常见偏差：删掉限定语，把可能说成必然，把批判说成赞同，合并不同概念，补入原文没有的解释，省略重复所承担的论证功能，或把原文歧义强行定译。
   - 回校后再次阅读中文，只修复由语义纠偏造成的新翻译腔；任何二次润色都必须再次对照对应法文，直到不再引入信息偏差。

## 工作流

### 1. 检查现场

1. 查看 `git status --short`，把已有修改视为用户内容。
2. 完整读取原文、译文骨架或草稿、术语表，以及前后课次的译文格式。
3. 统计原文 ID、脚注引用、脚注定义和图片；同时检查译文是否已有 `ids`、自定义笔记或阅读链接。
4. 阅读 `references/format-examples.md`。格式与活文件冲突时，以用户最新要求和活文件为准。

### 2. 建立映射并逐段翻译

1. 按 ID 顺序建立原文到译文的内部清单。
2. 分批翻译长课次，但每批都保持 ID 与内容绑定；不要把相邻段落的句子移入错误 ID。
3. 先解决法语句法、指代和论证关系，再写自然中文。
4. 同步处理原文脚注，避免正文翻完后遗漏文末注释。
5. 对照术语表；遇到歧义、义译或典故时立即按上述格式标记。

### 3. 执行 humanizer-zh 润色

在全部初译完成后使用 `$humanizer-zh` 逐段润色，但遵守以下边界：

- 保留拉康论证中的重复、回环、自我修正和口语节奏，不为追求“简洁”删掉逻辑环节。
- 删除翻译腔、机械连接词、无依据的强调、AI 式排比和宣传性词语。
- 调整中文长短句和标点，使其能自然朗读。
- 不改动 ID、注释编号、公式、希腊文、书名、原文括注和术语表统一译名。
- 不把润色结果视为已获确认的译文；下一步必须执行独立的法文信息保真复校。

若 companion skill 缺失，至少检查：冗余“此外/然而”、连续同构句、破折号滥用、生硬被动句、机械三段式、虚浮形容词、同义词循环和过度解释。

### 4. 润色后执行法文信息保真复校

1. 重新建立原文 ID 与润色后译文的对应清单，按顺序逐段核对，不以初译作为中介或依据。
2. 将每段拆成意义单元，检查人物、动作、受事、否定、情态、逻辑连接、限定范围、例证和结论是否完整对应。
3. 对每一处润色改写追问：删掉了什么、增加了什么、改变了何种强度、是否改变了谁对谁做什么，以及是否把原文的歧义或修辞功能抹平。
4. 发现信息偏差时，以法文为准回改；不要为了维护已有中文句子而替润色结果辩护。
5. 若信息差异或损失确实无法避免，使用正文 `[注]` 加段后 `> [注]`，说明：
   - 法文原义或字面结构；
   - 当前译法保留了什么、弱化或损失了什么；
   - 为何无法在正文中同时保全。
6. 回校完成后，再检查一次译注是否真的必要；能够通过正文准确表达的信息，不应推给译注。

### 5. 更新术语表

在正文定稿后补充新条目，并反查正文是否全部采用最终译名。不要为了“收集词汇”加入普通词；只加入会影响后续课次一致性、理解或检索的条目。

### 6. 验证

先运行聚焦校验：

```bash
python3 .agents/skills/translate-lacan-seminar8/scripts/validate_lesson.py \
  --source texts/s8-le-transfert/original/Leçon-xx.md \
  --translation texts/s8-le-transfert/translation/Leçon-xx.md
```

然后运行项目验证链：

```bash
git diff --check
python3 scripts/build_from_texts.py
./bin/mdbook build
```

最后检查：

- 已完成 humanizer-zh 后的逐 ID 法文回校，不是抽样复查。
- 润色前后涉及删减、增补、换义或强度变化的句子均已对照原文处理。
- 无法避免的信息差异或损失均有正文 `[注]` 与段后 `> [注]`；可直接修正之处未滥用译注。
- 渲染页 `book/s8-le-transfert/Leçon-xx.html` 存在。
- 渲染页包含全部唯一 ID、译文注释和图片引用。
- `git status --short` 只包含本次授权范围内的文件。
- 构建脚本显示的全仓库未译/缺失总数不能替代本课聚焦校验。

## 完成门槛

只有同时满足以下条件才能报告完成：

- 原文与译文 ID 完全一致，所有译文块非空。
- 原文脚注全部有正文引标和段后编号注释。
- 新增译注全部有正文 `[注]`，并排在原注之后。
- 义译、歧义和不确定处采用指定格式并给出必要说明。
- 新术语已查重并加入术语表，正文已回查。
- `$humanizer-zh` 润色或明确的回退润色已经执行。
- 润色后已按 ID 逐段重新对照法文，并修正增译、漏译、错译、强度变化、指代错误和论证方向偏差。
- 翻译与润色以信息保真为首要标准；无法避免的信息差异或损失已在译注中明确说明。
- 聚焦校验、`git diff --check`、文本构建和 mdBook 构建均通过。
- 已检查渲染页和最终改动范围。
