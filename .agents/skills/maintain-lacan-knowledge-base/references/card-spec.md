# 知识卡操作规范

本文件把当前 `知识库/README.md` 和现有卡片的共同模式整理成可执行模板。每次工作仍须先读取实时 README；若二者冲突，以实时 README 和用户本轮要求为准。

## 建卡前的吸收判断

同时满足以下条件才把解读、建言或注释整理成卡：

- 内容离开当前句后仍有独立阅读价值；
- 对人物、文本、事迹、历史背景或专业术语提供可复用知识；
- 能由原典、权威词典、图书馆资料或可靠研究核实；
- 不能由一张既有卡通过补充正文、来源和关联更自然地承载。

把页码与版本提示、内部导航、一次性微型词义或双关、无独立证据的联想，以及没有新增背景知识的引文留在原注释中。

## 新卡模板

```markdown
---
title: 不带编号且与文件名指向同一对象的可读标题
type: knowledge-card
verification: 已核实
tags:
  - 研讨班VIII
  - 领域/哲学
  - 人物/示例人物
  - 概念/示例概念
verified_at: YYYY-MM-DD
---

第一段直接界定知识对象、出处或问题，不重复标题。

后续段落说明关键事实、必要区别、常见误解和适用边界。只有主题本身是拉康概念、文本或生平时，才把拉康解释写入正文。

## 来源

- [资料标题](https://example.org/source)（法文；原典或该资料直接支持的内容）
- [[texts/s8-example/original/Leçon-01.md#s8-01-0001|本地法语原文 s8-01-0001]]（法文；本项目底本）

## 关联

[[知识库/相关卡片文件名.md|相关卡片标题]]

[[texts/s8-example/translation/Leçon-01.md#s8-01-0001|s8-01-0001]]
```

模板中的路径和标签只是结构占位，必须从实时仓库读取，禁止照抄。

## 标题与拆并

- 以人物、典故、著作、术语、概念、论证或事实问题作为一张卡的知识对象。
- 让标题揭示核心辨析，例如“X 的词源与 Y”“A 并非 B”，不要使用“补充资料”“知识点 12”等流程名称。
- 让文件名和 `title` 在语义上对应。文件名可省略中文与西文之间的排版空格、书名号或引号以保持路径简洁，不要求逐字符相同。
- 同一对象被多个研讨班或分段引用时，保留一张卡并累积关联。
- 同一人物下的两个独立问题可以分卡；若两张卡需要相同定义、相同证据和相同结论才能成立，应优先合并。
- 改名或合并前用标题、旧文件名和 Obsidian 链接文本搜索全仓库。

## verification 判定表

| 值 | 判定问题 | 正文处理 |
| --- | --- | --- |
| `已核实` | 原陈述的事实核心是否获得直接或可靠支持？ | 只写核实后的事实 |
| `部分准确` | 主旨是否成立但缺少限定、混合角色或断言过强？ | 写准确版本和必要边界 |
| `需更正` | 是否存在可定位的名称、出处、年代、人物或概念错误？ | 直接写正确事实，不复述错误 |
| `解释性延伸` | 是否超出文本事实或历史共识，只能作为解释？ | 明示推论边界，不伪装成史实 |

`verification` 面向促成知识卡的原解读、建言或注释中的事实陈述，不是给当前正文打质量分。

## 标签选择

按以下顺序选择 3–5 个标签：

1. 收录 `关联` 实际涉及的全部研讨班标签。
2. 至少选择一个 `领域/…`。
3. 从 `人物/…`、`作品/…`、`期刊/…`、`机构/…`、`团体/…`、`概念/…`、`传统/…`、`体裁/…` 中保留最核心的检索入口。
4. 只有辨析确实依赖语言、地区或时期时，才添加 `语言/…`、`地区/…`、`时期/…`。

标签只使用 Unicode 字母、数字、下划线、连字符和 `/`。把正文中的间隔号、空格和外文撇号在标签内改为连字符。知识卡不使用 `索引/…`，也不使用 `知识卡片`、`核实` 或 verification 取值等流程标签。

## 来源选择与写法

按问题类型选择能直接支持陈述的来源：

- 拉康研讨班概念：项目本地法语原文优先，再用校勘版、正式出版信息或学术研究补足。
- 弗洛伊德及其他作者：原文、可靠校勘文本或权威版本优先。
- 语言与词源：权威历史词典、语料库或专业词典。
- 哲学与古典学：原典、标准词典、学术版本和同行评审研究。
- 宗教与文学典故：原典文本与可靠版本史或研究资料。
- 数学与科学：标准教材、专业百科、原始论文或权威机构资料。
- 人物与历史：档案、图书馆目录、学术传记和机构资料。

每条外部来源写明“资料语言；用途或资料性质”。项目 `original/` 下的研讨班底本可由路径和链接标题共同标明其为本地法语原文。网页标题不能代替证据说明。外部来源不必凑固定数量，但关键事实需要足够交叉核对；一条直接原典通常比多条互相转载的二手网页更有价值。

## 关联规则

- `## 关联` 同时保存知识卡关系和翻译语境。先列相关知识卡，空一行后再列译文分段。
- 知识卡链接使用 `[[知识库/<文件名>.md|<目标卡 title>]]`。只连接知识对象、概念沿革、论证对照、人物—作品或常见混淆等实质关系。
- 把卡片链接作为对称关系维护：A 链接 B 时，同时在 B 的 `## 关联` 添加 A。旧单向链接可被检索器反向遍历，但更新时应补齐。
- 不要仅因共享 `研讨班…` 或宽泛 `领域/…` 标签就建链接；通常保留 1–5 张最有助于继续阅读的相关卡。
- 译文关联指向 `texts/<seminar>/translation/<lesson>.md`，并包含精确分段锚点；链接标签与锚点使用同一个分段 ID。
- 每个关联独占一行。知识卡链接按标题排列，译文链接按研讨班、课次和分段顺序排列，并全部去重。
- 若译文使用历史 `<!-- ids: ... -->` 合并映射，原分段 ID 仍可作为关联锚点，但必须确认该 ID 确实出现在映射中。
- 本地法语证据放在 `## 来源`，不要把 original 路径放进 `## 关联`。

## 更新范围

- 事实或来源发生变化：更新正文、来源、`verification` 和 `verified_at`。
- 仅新增同主题语境：追加关联与对应研讨班标签；不重写正文，不改 `verified_at`。
- 仅新增知识卡互链：同时编辑链接两端，不改两张卡的 `verified_at`。
- 仅修结构：保留事实措辞、核实状态和核实日期。
- 主题边界实际改变：先判断应改名、拆卡还是另建新卡，再检查所有反向链接。
